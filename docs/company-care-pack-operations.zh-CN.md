# 公司级护理知识包运营说明

护理知识属于公司级共享知识，不按国家站点复制。所有国家站点通过保留的 `__global__`
分区读取同一套产品护理规则；站点语言只决定使用哪个已审核的语言版本。

## 运营原则

- 同一 SKU、材质和产品结构使用同一套核心护理规则。
- 同一种语言只审核和发布一次，所有启用该语言的站点自动继承。
- 地区差异只放在地区覆盖层，不复制整份护理 SOP。
- 草稿和待审核内容不进入有效知识库。
- 没有目标语言的高风险步骤时，系统必须转人工，不能静默返回英文或临时机器翻译。

## 文档元数据

公司级护理文档应包含：

```yaml
tenant_id: __global__
care_pack_id: company-multi-material-care
care_pack_version: "1.0.0"
care_scope: company_global
care_locales:
  - en
  - zh-CN
```

护理步骤的 `step_id` 在所有语言中保持一致。每个已声明语言都必须有经过审核的步骤或通用
护理响应。`status: published` 与 `approval_status: approved` 缺一不可。

## 运行时能力

客服按以下顺序选择护理内容：

1. 精确语言，例如 `de-DE`；
2. 已审核的基础语言，例如 `de`；
3. 该语言的通用低风险护理；
4. 本地化转人工提示。

模型可以用于多语言语义检索，但不能把未审核的英语高风险护理步骤翻译后直接执行。
涉及电子部件、加热、维修、破损、霉菌、溶剂或材质不明时，必须遵循转人工规则。

## 发布流程

1. 产品负责人维护英文基准和材质规则。
2. 系统生成目标语言草稿。
3. 语言审核人和产品负责人审核目标语言。
4. 通过数字、单位、否定词、材质术语和步骤 ID 检查。
5. 在影子索引中验证检索和多语言回答。
6. 使用受保护的全局同步操作发布，并保留旧版本回滚。

运营人员不需要修改服务器环境文件、Docker 配置、Qdrant 或 PostgreSQL。当前全局同步仍是
受保护的 `knowledge:sync:global` 操作；后台运营入口上线前，平台操作员必须使用审计命令。

## 网站继承

新站点只需要配置主语言和启用语言。站点会自动继承对应的公司护理包，不创建站点副本。
如果某站点的同一 SKU 存在材质、电子结构或配件差异，必须登记为地区产品例外并单独审核，
不能静默复用全局 SOP。

## 验收状态

- `完整护理`：通用护理和站点实际销售材质的语言包均已发布；
- `基础护理`：目标语言只有通用低风险护理；
- `仅转人工`：没有可用的已审核语言内容或内容已过期。

网站上线不应被低流量语言阻塞，但每种启用语言的能力边界必须在后台可见。
